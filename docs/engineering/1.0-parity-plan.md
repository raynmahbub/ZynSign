# ZynSign 1.0 parity work plan

Status: **Planned / Partially implemented**. This is an engineering plan, not a promise that Apple platform restrictions, third-party behavior, or physical-device acceptance can be made to match other products. Existing branch changes are uncommitted. No release, tag, or migration is authorized by this plan.

See the [feature comparison](competitor-feature-comparison.md) for source snapshots, limitations and the current gaps against the named projects.

## Objective and evidence

Provide an understandable on-device workflow for importing or downloading an IPA, choosing an appropriate signing identity and provisioning profile, optionally modifying the app, signing, independently verifying the output, and handing it to a platform-supported installation channel. A successful local operation must not be presented as iOS accepting or launching the app. Account type, entitlements, device registration, certificate trust, revocation, and installation channel remain real constraints.

The older external validation record reports desktop `codesign` rejecting the tested application bundle and identifies gaps D1–D8, including CodeDirectory version, DER entitlements, resource seals, Info.plist binding and nested code. Its measurements describe the historical tested commit, not an execution of this branch. Fixes need fresh measurements, real iOS binary fixtures and physical-device evidence; do not remove guards or declare support just because local tests pass.

## Ordered milestones and gates

1. **Build and test baseline — Blocked here.** On macOS obtain actual schemes and destinations, run existing CI/XCTest, record versions and failures, then repair build and test regressions without fabricating success. This environment has neither Swift nor Xcode.
2. **Core signing — Partially implemented, device acceptance not established.** Reproduce the historical external-validation findings, fix real-binary admission and signing structures in small groups, and validate each with independent Apple tools. Cover nested frameworks, extensions, profiles, entitlements, real-device-compatible fixtures, interrupted jobs and unchanged source archives. Ship only after independently validated signed output and controlled device install/launch evidence.
3. **Installation — Blocked / Planned.** Evaluate HTTPS-hosted OTA manifest handoff and its lifecycle on supported devices; the current export does not host packages or observe installation. Separate this from the device bridge, whose unauthenticated transport is blocked. Do not assume an entitlement, certificate, localhost DNS/TLS arrangement, or `itms-services` behavior is universally available. Record a user-confirmed outcome as such, not as observed success.
4. **Identity and provisioning — Partially implemented.** Audit keychain access, secret handling, P12 import, certificate/profile matching, trust and expiry. Account provisioning and device authorization require real account/device testing; do not bundle private keys, bypass revocation, or promise unlimited free-account apps.
5. **Apps, repositories and downloads — Partially implemented.** Verify source formats and source identity, integrity, user-visible failures, storage and resume/cancel transitions. Foreground download behavior and opaque resume data remain limited; no silent-audio background workaround. Implement true OS background transfers only with a supported session lifecycle and relaunch handling, verified on devices.
6. **Tweaks, archive safety, and local transfer — Partially implemented.** Validate the new bounded archive decoder and hostile inputs and nested code mutations, and test compatibility without treating untrusted tweaks as safe. The LAN workspace is HTTP, not TLS; Basic Auth exposes credentials to the network and does not protect confidentiality. Complete race-resistant filesystem access, request timeouts and limits before treating it as hardened. WebDAV overwrite is deliberately refused until safe replacement is implemented.
7. **Guest runtime and paired-device features — Experimental / Blocked.** Loading guest code in the app process is not sandbox isolation or normal application execution. Do not claim LiveContainer-equivalent compatibility until demonstrated and threat-modeled. Device bridge transport requires authenticated TLS, correct framing, entitlements, cancellation and device tests. SideStore-style refresh requires an independently validated mechanism, not an assumption that an ordinary local socket grants it.
8. **Release readiness — Blocked.** Finish accessibility, privacy, diagnostics, migration, security and dependency audits; test supported iOS versions and hardware, failures and recovery, license compliance, performance and release CI. Define 1.0 scope from verified capabilities, not a blanket promise to reproduce every feature of every other app. No prerelease or stable promotion until gates are met.

## License and safety

ZynSign's repository license is MIT. Several comparable projects use GPL licenses; study behavior and public interfaces, but do not copy code or assets without a license and attribution review. Preserve existing third-party notices. Do not add certificates, account credentials, personal IPAs or private keys to the repository. Do not claim device or Apple-platform validation from Linux host tests.
